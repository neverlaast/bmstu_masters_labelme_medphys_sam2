# labelme_medphys_sam2

Программный инструмент для ручной и полуавтоматической разметки
биомедицинских и физических изображений.
Основа — неизменённый LabelMe 5.2.1; сегментация выполняется моделью SAM2.1
в отдельном процессе. Версия 0.5.0.

Основные возможности:

- промпты SAM2 (точки, прямоугольник, круг) и уточнение маски;
- поиск множества округлых объектов в круговой, прямоугольной или
  полигональной области с фильтрами формы и подавлением дублей;
- массовые операции: выбор, удаление и переназначение классов, undo/redo;
- проекты с реестром классов, контрольными суммами и автосохранением;
- 16/32-битные, многоканальные и многостраничные изображения;
- проверка разметки, экспорт LabelMe/COCO/YOLO/масок/CSV, экспорт датасета
  train/val/test, импорт COCO/YOLO;
- распространение объектов по кадрам последовательности (SAM2 video predictor);
- общий контракт модели для подключения других сегментаторов.

Устройство проекта — [docs/architecture.md](docs/architecture.md),
описание по смысловым блокам — [docs/blocks/](docs/blocks/).

## Установка и запуск

### Требования

- macOS или Linux; на Windows — через WSL (Ubuntu);
- Python ≥ 3.10, git, bash;
- около 3 ГБ на диске (PyTorch и веса модели) и интернет на время установки;
- желательно GPU: Apple Silicon (MPS) или NVIDIA (CUDA).

### Установка

```bash
git clone --recurse-submodules https://github.com/neverlaast/bmstu_masters_labelme_medphys_sam2.git
cd bmstu_masters_labelme_medphys_sam2
bash scripts/bootstrap.sh
bash scripts/download_sam2_checkpoints.sh
```
1. `git clone --recurse-submodules` скачивает проект вместе с исходным кодом
   SAM2, подключённым как git submodule в `third_party/sam2_upstream`. Если
   репозиторий склонирован без флага, выполните `git submodule update --init`.
2. `bootstrap.sh` создаёт виртуальное окружение `.venv` и выполняет
   `pip install -r requirements/dev.txt`. Зависимости разделены по файлам:

   | Файл | Содержимое |
   |---|---|
   | `requirements/base.txt` | интерфейс и обработка данных: PyQt5, numpy, OpenCV, tifffile и др. |
   | `requirements/sam2.txt` | `torch`, `torchvision` и SAM2 из `third_party/sam2_upstream` (editable) |
   | `requirements/dev.txt` | `base.txt` + `sam2.txt` + pytest, black, ruff |

   Стандартный PyTorch с PyPI поддерживает MPS на Apple Silicon и CUDA на
   Linux; отдельной установки под платформу не требуется.
3. `download_sam2_checkpoints.sh` скачивает веса с сервера Meta и проверяет
   SHA-256. Веса в репозиторий не входят (`*.pt` в `.gitignore`).

   ```bash
   bash scripts/download_sam2_checkpoints.sh            # large, модель по умолчанию
   bash scripts/download_sam2_checkpoints.sh tiny small # выборочно
   bash scripts/download_sam2_checkpoints.sh all
   ```

   Уже скачанные файлы с верной суммой пропускаются; прерванная загрузка
   продолжается; файл с неверной суммой удаляется.

### Запуск

```bash
bash scripts/run_app.sh                              # обычный запуск
bash scripts/run_app.sh /полный/путь/изображение.png # сразу открыть изображение
```

Сценарии сами переходят в корень проекта и используют `.venv`, активировать
окружение вручную не нужно. Приложение запускает SAM2 worker как дочерний
процесс на свободном порту `127.0.0.1`, ждёт готовности по `/health` (статус
«SAM2: starting / ready / failed» в строке состояния) и останавливает его при
выходе. Модель загружается при первом запросе сегментации. В меню
«Segmentation / SAM2» есть «Restart worker» и «Show worker log» — при ошибке
`WorkerResponseError` полный текст ошибки смотрите в журнале worker.

### Выбор устройства и модели

Параметры worker передаются через `--worker-arg`:

```bash
bash scripts/run_app.sh --worker-arg=--device=cpu    # auto | cpu | cuda | mps
bash scripts/run_app.sh --worker-arg=--backend=stub  # без модели, для проверки интерфейса
```

По умолчанию используется SAM2.1 large. Другая модель выбирается через
`--checkpoint`; конфиг (архитектура) подбирается по имени файла весов
автоматически. Если `--config` указан явно и не соответствует checkpoint,
worker не запустится и сообщит, какой конфиг нужен.

```bash
bash scripts/download_sam2_checkpoints.sh small
bash scripts/run_app.sh \
  --worker-arg=--device=mps \
  --worker-arg=--checkpoint=third_party/sam2_upstream/sam2.1_hiera_small.pt
```

Для весов с нестандартным именем (например, дообученных) `--config`
обязателен. Текущая модель, устройство и возможности показываются в
«Segmentation / SAM2 → Show model capabilities».

| Модель | `--checkpoint` | `--config` |
|---|---|---|
| tiny | `third_party/sam2_upstream/sam2.1_hiera_tiny.pt` | `configs/sam2.1/sam2.1_hiera_t.yaml` |
| small | `third_party/sam2_upstream/sam2.1_hiera_small.pt` | `configs/sam2.1/sam2.1_hiera_s.yaml` |
| base_plus | `third_party/sam2_upstream/sam2.1_hiera_base_plus.pt` | `configs/sam2.1/sam2.1_hiera_b+.yaml` |
| large (по умолчанию) | `third_party/sam2_upstream/sam2.1_hiera_large.pt` | `configs/sam2.1/sam2.1_hiera_l.yaml` |

Путь `--config` указывается относительно пакета `sam2`, а не корня проекта.

### Отдельный worker

Worker можно запустить отдельно — для отладки или на удалённой машине с GPU.
Если уже отвечает `http://127.0.0.1:8765` или задан `--worker-url` /
`MEDPHYS_WORKER_URL`, автозапуск не выполняется; `--no-worker` отключает его
полностью.

```bash
bash scripts/run_worker.sh --help
bash scripts/run_worker.sh --device mps \
  --checkpoint third_party/sam2_upstream/sam2.1_hiera_tiny.pt \
  --config configs/sam2.1/sam2.1_hiera_t.yaml   # терминал 1
bash scripts/run_app.sh                         # терминал 2: подключится к нему
```

Worker по умолчанию слушает только localhost; удалённый сервер требует
отдельной настройки безопасности.

## Базовый сценарий SAM2

1. Открыть PNG/JPEG/BMP/TIFF, в том числе 16/32-битное или многоканальное.
2. Через меню `Segmentation / SAM2` выбрать положительную/отрицательную точку,
   прямоугольник или круговой промпт одного объекта.
3. Нарисовать промпт. Диалог назначения класса для промпта не открывается.
   Точки, круги и рамки можно рисовать подряд без повторного выбора инструмента;
   `Finish prompt drawing` возвращает в режим редактирования.
   Окончательные аннотации не преобразуются во временные промпты.
4. Нажать `Run SAM2` или Ctrl+Enter. HTTP-запрос выполняется вне потока GUI.
5. Выделить кандидатов в панели `SAM2 Candidates`, принять или отклонить.
   Принятие выбранных не удаляет остальные кандидаты; повторный запрос заменяет
   прежние непринятые кандидаты только после успешного ответа.
6. Сохранить LabelMe JSON. Промпты и непринятые кандидаты в окончательный JSON
   не записываются. Принятый объект сохраняет происхождение, ID, оценку и
   информацию о модели.

Отмена запроса означает отмену применения результата, а не немедленное
прерывание вычислений в серверном процессе. При смене изображения устаревший
результат автоматически отбрасывается. Закрытие окна с активным запросом
откладывается до его завершения/таймаута, чтобы не уничтожить работающий QThread.

## Выделение, массовые операции и история

Обычные объекты выделяются на холсте средствами LabelMe или в списке с Ctrl
(Command) и Shift. В меню `Batch` доступны выбор
всех окончательных объектов, выбор по классу, групповое удаление и назначение
класса. Перед удалением отображается количество объектов и запрашивается
подтверждение.

Операции с геометрией, классами, промптами и кандидатами входят в ограниченную
историю снимков текущего изображения. Отмена использует штатное действие Undo,
повтор: `Batch → Redo` или Ctrl+Shift+Z; новая правка после отмены сбрасывает redo.
История не является долговременным журналом проекта и сбрасывается при смене
изображения.

## Поиск множества объектов и уточнение

Для одиночного объекта используйте `Run SAM2`. Можно много раз изменять точки
и ROI и запускать модель заново; каждое действие применяет текущие промпты.

### Несколько явных промтов или автоматический поиск

- `Run SAM2`: нарисуйте несколько кругов или рамок (можно смешивать) —
  каждая область обозначает один отдельный объект. Запуск обрабатывает их
  последовательно с использованием кэша embeddings, затем показывает вместе
  не более одного кандидата на область. Это не GPU-batch. Без кругов/рамок
  несколько точек по-прежнему совместно описывают один объект.
- При нескольких областях положительная точка должна лежать внутри
  одной из них (не на пересечении). Отрицательные точки применяются ко всем
  областям для исключения фона. Неоднозначные положительные точки вызывают
  предупреждение, а не автоматически назначаются соседнему объекту.
- `Find objects inside ROI`: одна большая область, внутри которой программа
  сама ищет неизвестное число объектов по сетке промтов. Если нарисованы
  несколько областей, программа предложит использовать `Run SAM2` либо оставить
  один ROI. `Find objects in whole image` ищет по всему изображению.
- При ошибке одного запроса предыдущие кандидаты на холсте сохраняются,
  частичный результат не применяется. Отмена прекращает отправку следующих
  областей; уже начатое вычисление worker может закончить.
Кеш embeddings сохраняет подготовку изображения между запросами.

Для настоящего уточнения с маской:

1. Выделите один кандидат или принятый SAM2-объект.
2. Добавьте положительные/отрицательные точки.
3. Выберите `Refine previously selected mask`.
4. Примите один из новых вариантов. Если уточнялся принятый объект, его
   геометрия заменится, сохранив ID; отмена восстанавливает прежний объект.

Модель получает низкоразрешённые logits выбранной маски и явные точки.
ROI массового поиска при этом не используется, чтобы не навязать одному
объекту положительные точки по всей области. Состояние уточнения
временно: очищается при перезапуске/очистке кеша и ограничено 128 масками.
При истечении состояния GUI предлагает обычный `Run SAM2`; геометрия уже
принятых объектов не исчезает. Число итераций не ограничено, но один запрос
ограничен 256 точками, а история текущего изображения — 100 изменениями.

Для поиска множества объектов:

1. Нарисуйте круг или прямоугольник; для произвольной области используйте
   `Polygon ROI: object search`.
2. В `Object search settings...` задайте сетку и фильтры.
3. Запустите `Find objects inside ROI`; без ROI используйте отдельное
   `Find objects in whole image`.
4. Выберите/примите найденные объекты. По умолчанию максимум: 64 кандидата
   за запрос, настройкой можно увеличить до 128.

Поиск выполняется по точкам сетки внутри ROI, а дубликаты подавляются по
IoU бинарных масок, не только bounding boxes. Фильтры включают площадь,
эквивалентный диаметр, отношение сторон ориентированного прямоугольника,
круглость, выпуклость, долю маски в ROI, оценку модели и касание границы.
Единицы геометрических фильтров: пиксели/пиксели², не микрометры.

При сильном перекрытии с существующей разметкой кандидат помечается, а
принятие требует подтверждения. Выбор окончательных объектов по ROI находится
в `Batch → Select final objects inside ROI (centroids)`; правило выбора — по
попаданию центроида, не по полному геометрическому включению.

Кеш: максимум два изображения и 128 МиБ features. Ключ включает хеш исходного
файла, модель/checkpoint/config, устройство, каналы, размеры и параметры
предобработки. `Clear worker cache` очищает features и состояния уточнения.
Предобработка — 8-битное RGB-представление с EXIF-ориентацией и настройками
`Image display`.

Маска сохраняется в метаданных как RLE, а её внешний полигон показывается на
холсте. Это ещё не полноценный растровый редактор/редактор отверстий. После
ручного изменения векторной геометрии прежний raster/logits помечается
устаревшим, а исходное предсказание остаётся отдельными метаданными.

Расширенный реальный smoke-тест:

```bash
.venv/bin/python scripts/smoke_sam2.py --variant small --device mps --advanced
```

## Проекты и классы

Меню `Project`:

- `New project from current image`: создаёт файл `*.medphys.json` с принятой
  разметкой текущего изображения. Промпты/кандидаты не входят в проект.
- `Add images`: добавляет изображения как новые пустые кадры.
  Существующие LabelMe sidecar-файлы не импортируются и не изменяются.
- `Open project`: проверяет схему, связи классов, геометрию, SHA-256 и размеры
  изображений. Потерянные изображения можно найти в новой папке по имени
  и контрольной сумме; неоднозначные совпадения отклоняются.
- `Save project` и Ctrl+S: сохраняют весь проект. Переход между кадрами
  предварительно сохраняет текущую разметку.
- `Save project as`: пересчитывает относительные пути для нового расположения.
  Для защиты от случайной замены другой проект существующий файл не заменяется.
- `Project classes`: имя, стабильный ID, цвет, описание, JSON атрибутов,
  допустимая геометрия, горячая клавиша назначения выбранным объектам,
  активность. Конфликтующие/зарезервированные клавиши запрещены.
- Переименование всей категории сохраняет её ID. Переименование выделенных
  объектов создаёт отдельную категорию с новым ID.
- Удаление используемой категории требует переноса объектов, удаления
  связанных объектов с подтверждением или деактивации категории.
- Отдельные `Undo/Redo project/class change` отменяют изменения структуры
  проекта/классов; привычные Undo/Redo продолжают работать для геометрии.

Проект хранит относительные пути и SHA-256, классы, геометрию/метаданные,
настройки SAM-поиска, яркость/контраст/масштаб, RGB-нормировку, политики кеша,
записи о моделях и журнал событий. Формат версионирован, неизвестная версия
или поля верхнего уровня отклоняются. Файл не содержит сырые изображения,
веса и tensors embeddings; это файл со ссылками, не переносимый архив.
Временные токены уточнения worker также не сохраняются.

Автосохранение по умолчанию каждые 60 секунд; интервал 10–3600 секунд
задаётся через меню. Запись атомарная, при повторном сохранении предыдущая
версия попадает в `.<project filename>.backups/` (10 последних по умолчанию).
Сохранение проверяет SHA-256 проектного файла и не затирает чужую версию,
если файл изменён извне. После ошибки автосохранение останавливается;
успешное ручное сохранение запускает таймер вновь.

Восстановление резервной версии: скопировать нужный JSON из backups в новый
файл `*.medphys.json` рядом с исходным проектом и открыть его.
Пока отдельного диалога восстановления нет. Undo не восстанавливается
после перезапуска; журнал сохраняется, но отражает агрегированные изменения
при сохранении и операции с классами, а не каждый жест мыши.
Открытие проекта, экспорт датасета и автосохранение выполняются в фоне
(см. «Фоновые файловые операции»).

## Свойства объекта

Выделите один окончательный объект на изображении или в списке. В панели
`Object properties` можно изменить класс, описание, статус проверки
(`unreviewed`, `accepted`, `corrected`, `rejected`, `imported`) и атрибуты.
Атрибуты задаются JSON-объектом, например
`{"diameter": 12.5, "cell_type": "A", "verified": true}`.
В проекте класс выбирается из реестра; его допустимая геометрия проверяется.

- `Apply` применяет все изменения одним действием undo/redo; `Reset` сбрасывает
  неприменённые правки. Ошибка JSON или класса не меняет объект частично.
- При смене выделения/кадра, сохранении или закрытии с неприменёнными правками
  появляется выбор: применить (`Save`), отбросить (`Discard`) или отменить переход
  (`Cancel`). `Apply` меняет объект в памяти; для записи на диск сохраните проект
  или LabelMe JSON обычным способом.
- `Object details (read-only)` показывает ID объекта/класса, цвет, источник,
  сохранённые сведения о модели, изображение, порядковый кадр проекта, track ID,
  время изменения, score и доступные метрики. Отсутствующие сведения отмечены
  `-`; текущая модель worker не подставляется вместо модели, создавшей объект.
- Время `modified_at` обновляется при изменении свойств и обычных правках
  окончательных объектов текущего кадра. Повторный вызов без изменений не
  обновляет время; undo/redo возвращает время соответствующего состояния.
- Промты и непринятые кандидаты доступны только для просмотра. При нескольких
  выделенных объектах панель не редактирует их совместно. Статус `rejected`
  сам по себе не удаляет окончательный объект и не заменяет отклонение кандидата.
- Если панель скрыта, включите `View → Object properties`.
  Она расположена во вкладке рядом с `Polygon Labels`, а не отдельной высокой
  панелью. Кнопки `Apply` и `Reset` остаются доступны при прокрутке полей.
  `View → Reset annotation panel layout` восстанавливает размеры и расположение
  боковых панелей без изменения разметки и настроек проекта.

Свойства сохраняются в проекте и LabelMe JSON. Служебные ID и геометрия
не меняются при редактировании атрибутов. Групповые свойства и фильтры списка
будут отдельными инструментами; эта панель работает с одним объектом.

## Научные изображения: 16/32 бит, каналы, стеки

Модуль `worker/imaging.py` общий для GUI и worker. Сырые данные (uint16, int32,
float, 1..N каналов) не изменяются; для разметки и SAM2 строится детерминированное
8-битное RGB-представление. Настройки отображения передаются в запрос (`display`) и
входят в ключ кеша embeddings, поэтому модель видит то же, что пользователь.

Меню `Image display`:

- `Display range and channels...`: режим auto (перцентили, по умолчанию 0,5–99,5 %
  на канал) или manual (абсолютные low/high), гамма, выбор 1–3 каналов
  в R,G,B. Разметка при смене отображения сохраняется.
- `Reset display to automatic`, `Image information` (dtype, каналы, кадры, диапазон).
- `Split multi-page image into frames...`: стек (T/Z/страницы) без потерь
  разбивается в `<имя>_frames/<имя>_f0001.tif`. При открытии многостраничного
  файла это предлагается автоматически, так как LabelMe хранит один JSON на файл.

Без пакета `tifffile` работают серые 16/32-битные и многостраничные файлы через
Pillow; многоканальные 16-битные TIFF и оси TCYX требуют `pip install tifffile`.
Экспорт копирует исходный файл, а не 8-битное представление. Настройки
отображения в режиме проекта сохраняются для каждого изображения
(`images[].display.scientific`), восстанавливаются при открытии и записываются в
`manifest.json` экспорта датасета; без проекта они живут до закрытия приложения.

## Импорт COCO / YOLO

Меню `Validate / Export → Import annotations: COCO JSON... / YOLO TXT...`
добавляет внешнюю разметку к открытому изображению как окончательные объекты
(флаг `imported`, `source=import_coco|import_yolo`, исходный ID/строка файла).
Если на изображении уже есть объекты, предлагается `Append` или
`Replace existing`; операция входит в Undo. Исходные файлы не изменяются.

- COCO: изображение сопоставляется по имени файла (или единственная запись),
  размер обязан совпадать. Поддерживаются полигоны, несжатый и сжатый RLE
  (без зависимости от pycocotools) и объекты только с bbox (прямоугольник).
  Многочастные полигоны и RLE хранятся как точная маска RLE с внешним контуром.
- YOLO: строки `class cx cy w h` (прямоугольник) и сегментационные полигоны.
  Имена классов берутся из `data.yaml`/`dataset.yaml`/`classes.txt` рядом
  с файлом или выше; иначе `class_<id>`. Путь по умолчанию ищется по схеме
  Ultralytics `images/… → labels/….txt`.
- Нераспознаваемые объекты пропускаются и перечисляются в отчёте; геометрия
  молча не исправляется (допускается только прижатие к границе на ≤ 0,5 px).
- При открытом проекте все классы должны существовать и быть активными
  в `Project classes`, иначе импорт отклоняется целиком.

Ограничения: импорт выполняется для текущего изображения; пакетный импорт
всего датасета в проект, keypoints/OBB YOLO и COCO-ключевые точки не поддерживаются.

## Проверка разметки и экспорт

В меню `Validate / Export`:

- `Validate current image annotations`: проверка принятых объектов.
- `LABELME`: JSON со ссылкой на копию исходного изображения.
- `COCO`: instance segmentation, несжатый RLE с сохранением отверстий.
- `YOLO`: полигоны с нормированными координатами и `data.yaml`.
- `BINARY_MASKS`: отдельный PNG 0/255 для каждого объекта, перекрытия допустимы.
- `MASKS`: бинарные PNG и индексированная семантическая маска с палитрой
  до 255 классов; выше 255 классов используется 16-битный PNG.
- `CSV`: ID, класс, растровая площадь, центроид, bounding box,
  происхождение и статус проверки.

Экспорт создаёт новую папку внутри выбранного каталога. В неё входят
неизменённая копия исходного изображения, карта классов и `export_report.json`.
Предыдущие экспорты, исходники и текущее состояние разметки не перезаписываются.
Промты и непринятые кандидаты исключаются. Для старых объектов без ID
создаётся детерминированный ID только в экспортном снимке.

Проверяются неизвестные классы при наличии `labels` в конфигурации,
невалидные/повторяющиеся ID, координаты вне кадра, самопересечения,
вырожденные фигуры, пустые и идентичные растровые маски. Разные вершины
с одинаковой растеризацией считаются дублем. Если проект не открыт,
классы вне проекта выводятся из текущего изображения, что явно указано в отчёте.
В проектном режиме используется вся карта классов, включая неактивные классы
у существующих объектов.
Стабильный порядок классов между независимыми экспортами требует задать
общий список `labels` в конфигурации.

YOLO не экспортирует маски с отверстиями/несколькими компонентами, чтобы
не терять геометрию молча. Индексированный PNG блокируется при перекрытии
объектов: используйте `BINARY_MASKS` или COCO. Экспорт ориентирован на
площадные фигуры: polygon, rectangle, circle; point/line/linestrip
не преобразуются в маски автоматически.

Все измерения заданы в пикселях; площадь/центроид вычисляются по растру,
а не по непрерывному векторному контуру. Для COCO bbox включает крайние
пиксели. Устаревшая SAM-маска после ручной правки не используется.
Это экспорт одного текущего изображения; весь проект с разбиением
train/val/test выгружается через `Project → Export dataset` (см. ниже).
Общая память масок в проверке ограничена 512 МиБ.

## Экспорт датасета (train/val/test)

`Project → Export dataset (train/val/test)...` выгружает весь проект в COCO, YOLO
(сегментация) или маски (`*_semantic.png` — значение класса, `*_instance.png` —
номер объекта, uint16). Параметры: доли выборок, seed, включение пустых
кадров, только проверенные объекты (`accepted`/`corrected`).

- Разбиение детерминировано seed; кадры одного стека (`<имя>_frames/`)
  попадают в одну выборку, чтобы избежать утечки почти одинаковых кадров.
- Перед записью проверяются все кадры: геометрия, SHA-256 файлов, совместимость с YOLO,
  перекрытия для масок. При ошибках показывается полный список, ничего не пишется.
- Папка `medphys_dataset_<формат>_<id>` публикуется атомарно; оригиналы
  копируются без изменений (16-битные остаются 16-битными), совпадающие имена
  получают суффикс ID.
- `manifest.json` — кадр → выборка/группа/SHA; `report.json` — seed, доли, число
  кадров и объектов по классам, предупреждения о пустых выборках, отпечаток
  разбиения для воспроизводимости.

Экспорт выполняется в фоне с прогрессом и отменой. Стратификация по классам
не выполняется.

## Распространение объектов по кадрам (SAM2 video predictor)

`Segmentation / SAM2 → Propagate objects to other frames...` (требуется проект).
Выделенные (или все) объекты текущего кадра отслеживаются вперёд, назад или в обе
стороны на N соседних кадров проекта того же размера (порядок — порядок кадров в
проекте; для стеков сначала `Split multi-page image`).

- Кадры подаются в SAM2 из памяти через то же 8-битное представление, что и в окне
  (настройки `Image display`), с нормализацией как в загрузчике SAM2, без промежуточного JPEG.
- Результаты записываются как предложения: `source=sam2_propagation`,
  `review_status=unreviewed`, точная маска RLE и `track_id` исходного объекта
  (идентичность объекта между кадрами). Повторный запуск заменяет только
  непроверенные предложения этого трека; ручную и проверенную разметку не трогает.
- Операция входит в Undo проекта и журнал; отчёт показывает число добавленных,
  сохранённых и «потерянных» моделью объектов.

Ограничения: до 300 кадров и 200 объектов за запуск; только бекенд `sam2_real`
(video predictor загружается лениво и занимает дополнительную память). Worker
однопоточный: на время распространения другие запросы ждут; «Cancel» отбрасывает
результат, но не прерывает вычисление в worker. На Mac (MPS, hiera_tiny) ≈ 1,5 с/кадр.

### Видео

`File → Open video...`, `Project → Import video...`, перетаскивание файла в окно
 или `bash scripts/run_app.sh cells.mp4` — декодирует
видео (mp4/avi/mov/mkv/…, через OpenCV) в последовательность PNG без потерь и
добавляет кадры в проект в порядке времени; без открытого проекта создаётся
новый рядом с видео. В диалоге задаются первый/последний кадр и шаг (по
умолчанию шаг подбирается так, чтобы уложиться в 300 кадров одного запуска
propagation; предел импорта — 5000 кадров). Соответствие файл → номер кадра →
время сохраняется в `<папка кадров>/video_frames.json`, факт импорта — в журнале
проекта. Далее: разметить объекты на одном кадре и выполнить
`Propagate objects to other frames...`.

Переход между кадрами проекта (список файлов, `Next/Prev Image`, клавиши `D`/`A`)
сохраняет проект автоматически и не спрашивает подтверждения; вопрос о
сохранении задаётся только при закрытии проекта или программы.

Проверка на реальной модели (синтетическое видео, два движущихся диска, IoU с
эталоном): `.venv/bin/python scripts/smoke_video.py --device cpu --variant tiny`.

## Фоновые файловые операции

Долгие операции выполняются в отдельном потоке (`app/gui/io_jobs.py`) с индикатором
прогресса и кнопкой Cancel; поток работает со снимком данных и не трогает GUI:

- экспорт датасета (по замороженной копии проекта; отмена ничего не публикует);
- открытие проекта с проверкой SHA-256 всех изображений;
- разбиение многостраничного TIFF на кадры;
- автосохранение (без диалога, статус в строке состояния). Правки, сделанные
  во время сохранения, остаются помеченными как несохранённые.

Ручное сохранение, переход между кадрами и закрытие остаются синхронными и
сначала дожидаются идущего автосохранения (без конфликта хешей). Пока идёт
открытие проекта, операции со структурой проекта блокируются; закрытие окна
при активной операции отменяет её и просит закрыть повторно.

## Другие модели: общий адаптер

Контракт `worker/adapters.py::SegmentationAdapter` включает:

`load`, `unload`, `get_info`, `get_capabilities`, `clear_cache`,
`prepare_image`, `compute_embedding`, `segment_prompt`, `generate_masks`,
`process_sequence`.

`AdapterCapabilities` сообщает о поддержке точек, box, уточнения маски,
автоматической генерации, embeddings и последовательностей. Неподдерживаемый
режим отклоняется явно. Реальный SAM2 реализует image-путь контракта; распространение по кадрам
выполняется отдельным endpoint `POST /propagate` (флаг `sequence`
контракта пока остаётся `False`).

Нейтральные структуры доступны из `worker.model_registry`: `Point`, `Box`,
`MaskCandidate`, `ModelInfo`, `InferenceRequest`, `InferenceResponse`.
Старые имена `Sam*` сохраняются для совместимости. Модельно-зависимое
prepared/embedding-состояние остаётся непрозрачным для worker и GUI.

Для новой модели создайте доверенный установленный Python-модуль с фабрикой,
принимающей `checkpoint_path`, `config_path`, `device`, и возвращающей адаптер
с указанным контрактом. Запуск:

```bash
bash scripts/run_worker.sh --adapter my_package.my_model:create_adapter \
  --device cpu --checkpoint /path/to/weights --config /path/to/config
```

Контракт проверяется при старте без загрузки весов. Можно также регистрировать
фабрики через `register_adapter` для программного использования.
Проектные JSON и HTTP-запросы не импортируют plugin-код и не переключают модели.
Фабрика исполняет Python-код с правами worker, поэтому используйте только
доверенные модули. Функциональность другой нейросети требует её собственной
реализации адаптера, зависимостей и весов; их автоустановки здесь нет.

Проверенный второй backend для демонстрации контракта:

```bash
bash scripts/run_worker.sh \
  --adapter worker.plugins.threshold_demo:create_adapter --device cpu
```

Это обычный пороговый алгоритм для тёмных объектов на светлом фоне,
НЕ нейросеть и НЕ медицинская модель. Он демонстрирует автоматический
поиск через тот же API и GUI, отказывается от интерактивных промптов.
Для SAM2 используйте обычный запуск worker без `--adapter`.

В меню `Segmentation / SAM2` доступны `Show model capabilities`
и `Unload current model`. API: `GET /model`, `POST /model/unload`;
загрузка выполняется при следующем запросе сегментации. Возможности и
сведения о модели также возвращаются health/segmentation-ответами.

## Тесты

Для реальных Qt-виджетов предусмотрены offscreen-тесты:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

Тесты не требуют скачивания весов. Они проверяют промты без диалога класса,
реальные API виджетов, принятие/отклонение, сохранение без временных объектов,
undo/redo, подтверждение удаления, неблокирующий запрос и отбрасывание
отменённого/устаревшего результата. Проверка реального инференса выполняется
отдельно и не подменяется результатом заглушки.

Проверить реальную модель на искусственном изображении:

```bash
.venv/bin/python scripts/smoke_sam2.py --variant small --device mps
```

Проверка создаёт тестовый PNG и JSON-отчёт в `logs/smoke`, не меняя
пользовательские изображения. Это smoke-тест работоспособности, а не оценка
качества сегментации клеток или клинической пригодности.

Для проверки интерфейса без модели предусмотрен явно демонстрационный backend:

```bash
bash scripts/run_worker.sh --backend stub
```

Его геометрия искусственная и не предназначена для разметки данных.

## Структура проекта

Подробная схема — [docs/architecture.md](docs/architecture.md).

- `app/gui` — окна на базе LabelMe, меню, фоновые задачи.
- `app/core` — логика без Qt: история, выбор, экспорт, импорт, экспорт датасета.
- `app/worker_api` — схемы протокола и HTTP-клиент.
- `project_format` — формат проекта `*.medphys.json`.
- `worker` — процесс инференса: адаптеры моделей, SAM2, кеш, обработка
  изображений, распространение по кадрам.
- `tests` — автоматические тесты; `scripts` — запуск и служебные сценарии.
- `third_party/labelme_upstream` — LabelMe 5.2.1; `third_party/sam2_upstream` — SAM2.

Файлы `third_party` не изменяются; дополнительное поведение реализуется
в собственном коде. Для NumPy 2.x `app/compat.py` заменяет расчёт расстояния
до отрезка в LabelMe (иначе GUI падал при наведении на контур).
