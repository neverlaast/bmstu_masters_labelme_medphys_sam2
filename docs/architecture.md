# Архитектура

Приложение состоит из двух процессов, связанных HTTP-протоколом на localhost:

```
GUI-процесс (клиент)                              worker-процесс (сервер)
PyQt5, LabelMe 5.2.1                              PyTorch, SAM2

app/gui                                            worker/main.py
  окна, меню, фоновые задачи                         HTTP-сервер
app/core                                           адаптер модели
  логика разметки без Qt                             реализация контракта сегментации
project_format                                     кеш embeddings
  формат *.medphys.json                              временные признаки изображений
app/worker_api                                     распространение по кадрам
  схемы запросов и HTTP-клиент                       обработка последовательностей

                       HTTP-запрос, тело: JSON
              ─────────────────────────────────────────►
                       HTTP-ответ, тело: JSON
              ◄─────────────────────────────────────────

Общий модуль: worker/imaging.py
   чтение, нормализация и подготовка изображений для GUI и worker.
```

Модель работает в отдельном процессе: вычисления и память PyTorch не блокируют
интерфейс, модель можно выгрузить или заменить без перезапуска GUI, а сбой
инференса не уничтожает несохранённую разметку.

## Каталоги

| Каталог / файл | Назначение |
|---|---|
| `app/main.py`, `app/paths.py`, `app/compat.py` | запуск, пути к стороннему коду, совместимость LabelMe с NumPy 2 |
| `app/gui/labelme_window.py` | главное окно — наследник окна LabelMe: промты SAM2, кандидаты, массовые операции, отображение изображений, импорт |
| `app/gui/project_window.py` | режим проекта: открытие/сохранение, классы, экспорт датасета, распространение, фоновые операции |
| `app/gui/io_jobs.py`, `worker_task.py` | фоновые потоки для файловых операций и запросов к worker |
| `app/gui/generation_dialog.py`, `project_classes_dialog.py` | диалоги настроек поиска и реестра классов |
| `app/core/history.py`, `selection.py`, `geometry.py` | undo/redo, выбор объектов, геометрия |
| `app/core/export.py`, `importers.py`, `dataset_export.py` | проверка и экспорт изображения, импорт COCO/YOLO, экспорт датасета |
| `app/worker_api/` | pydantic-схемы протокола, HTTP-клиент, ошибки |
| `project_format/` | модели проекта, атомарное чтение/запись, операции с классами, JSON Schema |
| `worker/main.py` | HTTP-сервер: `/health`, `/model`, `/segment`, `/propagate`, `/cache/clear`, `/model/unload` |
| `worker/adapters.py`, `model_registry.py` | общий контракт модели, адаптеры SAM2 и заглушки, реестр фабрик |
| `worker/predictors/`, `postprocess/`, `cache/` | вызов SAM2, маска → полигон/RLE, фильтры и NMS, LRU-кеш embeddings |
| `worker/imaging.py` | чтение 8/16/32-бит и многоканальных изображений, окно интенсивностей, разбиение стеков |
| `worker/propagation.py` | трекинг масок SAM2 video predictor |
| `worker/plugins/threshold_demo.py` | пример второго, не нейросетевого адаптера |
| `tests/` | модульные и offscreen GUI-тесты |
| `scripts/` | запуск GUI и worker, установка окружения, загрузка весов, smoke-тест модели |
| `third_party/` | LabelMe 5.2.1 и SAM2 без изменений |

## Потоки данных

Интерактивная сегментация: промпты на холсте → `SegmentationRequest`
(точки, box, круг, настройки отображения) → worker → маски → кандидаты
в панели `SAM2 Candidates` → принятие пользователем → окончательные объекты.

Проект: `*.medphys.json` хранит относительные пути и SHA-256 изображений,
классы, аннотации (полигон и RLE исходной маски), настройки отображения
и журнал. Изображения и веса в файл не входят.

Экспорт: снимок проекта → проверка всех кадров → запись во временный каталог →
атомарное переименование. Исходные файлы и разметка не изменяются.

## Особенности

- Сторонний код не редактируется; поведение меняется наследованием и узкими
  адаптерами (`app/compat.py`, подмена загрузчика изображений).
- Временные объекты (промпты, кандидаты) не сохраняются как разметка.
- Ошибки входных данных сообщаются явно; геометрия и интенсивности
  молча не исправляются.
- Записи атомарны; долгие операции выполняются в фоне по снимку данных.
